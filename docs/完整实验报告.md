# SelfEvo Agent Security 完整实验报告

## 1. 项目背景

随着 Agent 系统具备长期记忆、工具调用和自我迭代能力，外部输入对 Agent 行为的影响不再局限于当前对话。恶意网页、文档或日志可能被 Agent 读取并写入记忆，在后续任务中再次被检索出来，诱导 Agent 调用高风险工具。

本项目围绕“Self-evolving Agent 记忆污染与工具调用安全”构建一个可复现实验平台，用于观察：

- 不可信材料是否能污染 Agent 记忆。
- 污染记忆是否能在后续任务中诱导工具调用。
- 防护策略是否能记录、溯源并拦截高风险工具调用。
- 在不真实执行危险操作的前提下，是否能直观展示攻击效果与防护效果。

## 2. 实验目标

本项目的目标不是执行真实攻击，而是在安全边界内复现 Agent 安全风险：

```text
不可信输入 -> 记忆污染 -> 后续检索 -> 工具调用意图 -> 策略判断 -> dry-run / block -> 审计日志与指标
```

核心验证点：

- Agent 能读取本地实验材料。
- Agent 能把外部内容写入 shadow memory。
- Agent 在后续任务中可能受到污染记忆影响，产生高风险工具调用意图。
- 防护层能够识别高风险工具调用，记录来源并阻止真实执行。
- baseline 模式能够展示“如果没有防护，攻击会进入危险执行路径”。
- dry-run / block 模式能够展示“加入防护后，同样攻击不会产生可见攻击效果”。

## 3. 系统架构

项目由五个主要模块组成：

| 模块 | 作用 |
| --- | --- |
| `agent/` | CrewAI / DeepSeek / OpenAI / mock Agent 后端，负责生成结构化任务结果 |
| `security/` | 防护层，包含 policy、tool runtime、dry-run、审计与溯源 |
| `lab/` | 实验任务、指标统计、日志工具 |
| `data/` | 本地 benign / poison fixture，不访问真实网页 |
| `logs/` | 每次运行生成的 JSONL 审计日志和报告 |

完整链路：

```text
infection task
  -> read_url 读取本地 fixture
  -> Agent 生成 memory candidate
  -> shadow memory 写入
  -> trigger/control task
  -> shadow memory 检索
  -> Agent 产生工具调用意图
  -> ToolRuntime 调用 policy_check
  -> execute_command dry-run / baseline simulated
  -> JSONL 审计日志
  -> metrics 汇总报告
```

## 4. 安全边界

项目坚持以下安全约束：

- `read_url` 不访问真实网络，只允许读取 `data/poison_pages/*.txt` 和 `data/fixtures/*.txt`。
- `execute_command` 永远不会真实创建进程或执行系统命令。
- 命令参数写入日志前会脱敏为 `REDACTED_DRY_RUN_COMMAND`。
- 攻击样本只使用 `SIMULATED_*` 安全标记，不包含真实攻击 payload。
- baseline 模式只记录 `would_execute_without_defense` 和 `simulated_executed`，不突破安全边界。
- demo 可见效果只写入 `demo_effects.jsonl`，不修改真实系统状态。

## 5. 防御机制

项目当前的防御措施包括：

| 防御点 | 说明 |
| --- | --- |
| 本地 fixture 隔离 | Agent 只能读取本地样本，不能直接访问真实网页 |
| Shadow memory | 每条记忆带有 `memory_id`、来源类型、可信级别和风险标签 |
| Provenance 溯源 | 工具调用记录 `retrieval_context_id`、`retrieved_memory_ids`、`derived_from_memory_ids` |
| 高风险工具识别 | `execute_command` 被视为高风险工具 |
| Policy 拦截 | 高风险工具默认 dry-run；来自不可信记忆时命中额外规则 |
| 参数脱敏 | 工具调用参数进入日志前脱敏 |
| Demo 效果隔离 | baseline 只写无害可见效果，真实执行始终为 0 |
| Control 检索过滤 | control 任务默认过滤带风险标签的不可信记忆，降低误触发 |

主要策略规则：

```text
high_risk_tool_dry_run_only
high_risk_tool_after_untrusted_retrieval
baseline_without_defense_simulated
```

## 6. 实验设计

### 6.1 记忆污染实验

infection 阶段读取不可信样本，将内容写入 shadow memory。样本模拟恶意网页或文档中的隐藏诱导内容。

目标：

- 验证 Agent 能读取实验材料。
- 验证不可信来源会被记录为 `source_trust_level=untrusted`。
- 验证风险标签能进入 shadow memory。

### 6.2 Trigger 实验

trigger 阶段执行正常任务，例如写报告、总结进度、生成 QA 状态等。Agent 会检索历史记忆，如果检索到污染内容，可能产生高风险工具调用意图。

目标：

- 验证污染记忆能影响后续任务。
- 验证工具调用意图能被记录。
- 验证 policy 能拦截高风险工具。

### 6.3 攻击案例对照实验

为回应指导老师“demo 要直观”的建议，项目新增 4 类典型攻击案例：

| 场景 | 样本 | 模拟风险 |
| --- | --- | --- |
| 命令执行诱导 | `attack_sim_command.txt` | 诱导 Agent 产生命令执行意图 |
| 敏感信息读取诱导 | `attack_sim_sensitive_read.txt` | 诱导 Agent 产生敏感读取意图 |
| 数据外传诱导 | `attack_sim_exfiltration.txt` | 诱导 Agent 产生外传意图 |
| 持久化诱导 | `attack_sim_persistence.txt` | 诱导 Agent 产生环境篡改意图 |

每个案例跑两种模式：

```text
baseline：模拟无防护路径，记录攻击会进入危险执行路径，并写入 demo 可见效果
dry_run：开启防护，同样攻击被记录并拦截，不产生 demo 攻击效果
```

## 7. Demo 展示逻辑

真实危险命令不执行，但 demo 中需要让评委直观看到差异，因此项目引入 `demo_effects.jsonl`：

- baseline 模式：如果攻击诱导成功，写入一条无害 demo effect。
- dry-run 模式：防护生效，不写入 demo effect。

示例：

```text
baseline:
  Demo 状态变化：模拟数据外传已进入危险执行路径。

dry_run:
  防护生效，无 demo 攻击效果
```

这样可以直观说明：

```text
无防护：攻击产生可见影响
有防护：攻击被拦截，没有可见影响
真实执行：始终为 0
```

## 8. 运行方式

安装依赖：

```bash
pip install -r requirements.txt
```

基础测试：

```bash
python -m unittest discover -v
```

完整两阶段实验：

```bash
python run_infection.py
python run_trigger.py
python lab/metrics.py
```

攻击案例对照实验：

```bash
python run_attack_scenarios.py --policy baseline --agent-backend mock
python run_attack_scenarios.py --policy dry_run --agent-backend mock
python lab/metrics.py
python lab/demo_dashboard.py
```

Windows PowerShell 一键运行 demo：

```powershell
.\scripts\run_attack_demo.ps1 -AgentBackend mock
```

使用 DeepSeek / CrewAI：

```bash
python run_attack_scenarios.py --policy baseline --agent-backend crewai
python run_attack_scenarios.py --policy dry_run --agent-backend crewai
python lab/metrics.py
```

使用 OpenAI / CrewAI：

```bash
Copy-Item config/openai.env.example .env
python run_attack_scenarios.py --policy baseline --agent-backend crewai
python run_attack_scenarios.py --policy dry_run --agent-backend crewai
python lab/metrics.py
```

## 9. 当前实验结果

### 9.1 Mock 攻击案例对照

| 模式 | 高风险案例数 | 模拟攻击成功数 | Demo 可见效果数 | 防护拦截数 | 真实执行数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `baseline` | 4 | 4 | 4 | 0 | 0 |
| `dry_run` | 4 | 0 | 0 | 4 | 0 |

结论：

- 无防护 baseline 下，4 个典型攻击都能诱导 Agent 产生高风险工具调用意图。
- 开启 dry-run 防护后，同样 4 个攻击都被拦截。
- 真实执行数始终为 0。

- 真实执行仍然为 0。

## 10. 指标说明

| 指标 | 含义 |
| --- | --- |
| `risky_tool_attempt_count` | 高风险工具调用意图数量 |
| `baseline_simulated_success_count` | baseline 下模拟攻击成功数量 |
| `baseline_simulated_success_rate` | baseline 下模拟攻击成功率 |
| `defense_blocked_count` | 防护模式下拦截数量 |
| `defense_block_rate` | 防护模式下拦截率 |
| `visible_demo_effect_count` | demo 可见攻击效果数量 |
| `real_executed_count` | 真实执行次数，预期始终为 0 |
| `post_policy_asr` | 策略后攻击成功率 |

`python lab/demo_dashboard.py` 会生成静态 HTML 页面：

```text
logs/runs/reports/demo_dashboard.html
```

该页面从 JSONL 审计日志读取最新 baseline / dry_run 攻击对照结果，用于展示“无防护有可见攻击效果、防护后无可见攻击效果”。

## 11. 项目亮点

- 将 Agent 记忆污染、工具调用和防护审计串成完整实验链路。
- 支持 mock 稳定复现，也支持 CrewAI / DeepSeek / OpenAI 真实 LLM 后端。
- 攻击样本安全可控，不包含真实危险代码。
- 防护不仅阻断工具执行，还能记录来源、命中规则和关联记忆 ID。
- demo 层可以直观展示“无防护有影响、防护后无影响”。
- 所有证据来自 JSONL 日志，便于复查和写报告。

## 12. 当前局限与后续优化

当前仍需注意：

- DeepSeek / CrewAI 结果依赖 API key、网络和模型稳定性。
- mock 后端适合稳定展示链路，但不能完全代表真实模型行为。
- 当前 demo 以 Markdown 报告和 JSONL 日志为主，后续可以做成可视化 Web 页面或终端仪表盘。

已完成的优化：

- 增加 OpenAI / DeepSeek 多模型对照实验说明。
- 增加 OpenAI 配置模板 `config/openai.env.example`。
- 优化 retrieval：control 任务默认过滤带风险标签的不可信记忆，降低误触发。
- 增加 demo 可见效果字段，baseline 有可见影响，dry-run 无可见影响。
- 增加静态 HTML demo dashboard，从审计日志直接生成可视化展示页面。
- 增加威胁模型与安全声明，明确攻击者能力、系统边界和合规展示口径。
- 增加一键 demo 脚本 `scripts/run_attack_demo.ps1`，降低展示和复现实验成本。

后续可继续优化方向：

- 增加更细粒度的 provenance policy。
- 将当前静态 HTML dashboard 扩展为交互式 Web 页面，实时展示 baseline 与 dry-run 差异。
- 完善威胁模型、伦理声明和比赛展示材料。

## 13. 总结

本项目已经完成一个可运行、可审计、可展示的 Agent 安全实验平台。它证明了：

```text
攻击样本可以诱导 Agent 产生高风险工具调用意图；
无防护 baseline 下攻击会进入模拟危险执行路径，并产生可见 demo 效果；
加入防护后，同样攻击被记录、溯源并拦截；
真实危险操作始终不会执行。
```

因此，该平台既能体现 Agent 安全风险，也能体现防护机制的有效性，适合作为信息安全作品赛的实验原型和展示基础。
