# 威胁模型与安全声明

## 1. 威胁模型

本项目关注 Self-evolving Agent 在长期记忆和工具调用能力下的安全风险。攻击者不能直接控制系统工具，但可以控制 Agent 读取到的外部材料，例如网页、文档、日志片段或实验 fixture。

攻击链路如下：

```text
攻击者控制外部内容
  -> Agent 读取内容
  -> 内容被写入长期记忆
  -> 后续正常任务检索到污染记忆
  -> Agent 产生高风险工具调用意图
  -> 防护层记录、溯源并拦截
```

## 2. 攻击者能力假设

攻击者可以：

- 提供包含隐藏诱导语句的不可信文档。
- 影响 Agent 的记忆写入内容。
- 等待后续正常任务触发污染记忆。
- 诱导 Agent 产生工具调用意图。

攻击者不能：

- 直接绕过 `ToolRuntime` 调用系统命令。
- 直接访问真实网络、真实密钥或真实文件系统。
- 修改 policy 决策逻辑。
- 让 `execute_command` 真实创建进程。

## 3. 防护目标

本项目的防护目标不是让 Agent 永远不产生风险意图，而是保证：

- 风险意图可被检测。
- 风险来源可被追溯。
- 高风险工具不会真实执行。
- 攻击/防御效果可以被审计日志复核。
- demo 能直观看到差异，但不会造成真实危害。

## 4. 安全边界

项目设置了多层安全边界：

| 边界 | 说明 |
| --- | --- |
| 本地 fixture | `read_url` 只读取本地 `.txt` 样本，不访问真实网页 |
| 工具 dry-run | `execute_command` 始终不真实执行 |
| 参数脱敏 | 命令参数写入日志前脱敏 |
| Shadow memory | 记录来源、可信级别、风险标签和 memory id |
| Policy check | 高风险工具调用被 dry-run 或 block |
| Demo effect | baseline 只写无害可见效果，不改变真实系统状态 |

## 5. 为什么不提供真实攻击 payload

如果让模型直接生成真实攻击代码、真实命令或真实外传 payload，通常会触发安全限制，也不适合作为比赛作品直接执行。因此本项目采用“安全等价模拟”：

```text
真实攻击 payload
  -> 替换为 SIMULATED_* 安全标记
真实命令执行
  -> 替换为 would_execute_without_defense / simulated_executed
真实系统影响
  -> 替换为 demo_effects.jsonl 中的无害可见效果
```

这种设计保留了安全研究中重要的证据链：

- Agent 是否产生危险工具调用意图。
- 该意图是否来自不可信记忆。
- 无防护时是否会进入危险执行路径。
- 有防护后是否被拦截。

同时避免真实危害。

## 6. 评审展示口径

推荐展示方式：

```text
第一步：展示 baseline
  攻击样本诱导 Agent 产生高风险工具调用意图；
  系统记录 would_execute_without_defense=true；
  demo 页面显示攻击产生可见影响。

第二步：展示 dry_run
  使用同样攻击样本；
  防护层命中 high_risk_tool_after_untrusted_retrieval；
  demo 页面显示防护生效，无攻击效果。

第三步：强调安全边界
  两组实验中 real_executed_count 始终为 0。
```

## 7. 合规说明

本项目仅用于防御性安全研究和教学展示：

- 不包含真实漏洞利用代码。
- 不包含真实恶意命令。
- 不包含真实密钥、真实外传地址或真实持久化逻辑。
- 不执行真实危险操作。
- 所有攻击效果均为本地无害模拟。

因此，项目可以展示 Agent 安全风险和防护效果，同时保持安全、可控、可复现。
